## Root cause

`main-session-restart-recovery` (OpenClaw 2026.9.8) re-dispatches interrupted turns with a synthetic system message and the original delivery route. When the recovered turn invokes `tool=exec` to run `systemctl --user stop openclaw-gateway`, the structure is:

```
recovered turn  →  tool=exec (systemctl stop)  →  waits for gateway exit  ↘
                                                                       DEADLOCK
Gateway main     →  waits for background exec to settle                  ↗
```

`KillMode=mixed` does not rescue this — the gateway main process is still alive (just unable to exit), and the exec broker holds the active session open. The deadlock persists until external SIGKILL.

**Why 2026.9.8 didn't fix it:** CHANGELOG entry `(#161260)` "prevent stuck Anthropic background-command turns" only addresses the Anthropic background-command path. The deadlock here is `minimax/MiniMax-M3` going through `main-session-restart-recovery`, which is a different code path.

## Resolution path

1. User SIGKILLed the deadlock; brought service back to clean state
2. Disabled Feishu plugin (incidental — channel-announcement had already failed at 12:42:35 with "Channel is unavailable: feishu", but disabling stops further announce attempts)
3. User issued `systemctl --user restart openclaw-gateway.service` from an **independent terminal** (not via Gateway-internal `tool=exec`)
4. Feishu re-enabled via `openclaw config set plugins.entries.feishu.enabled true` + `channels status --probe` (hot-reload verified — no Gateway restart needed)
5. drop-in `upgrade-override.conf` (which contained `Restart=no` from the original incident) moved to `~/openclaw-upgrade-debug/disabled-dropins/`
6. `systemctl --user daemon-reload` (config reload, **not** Gateway restart)
7. `Restart=always / RestartUSec=5s / KillMode=mixed` verified via `systemctl --user show`

## Permanent rules (recurring)

These rules were extracted during the incident response. They apply whenever any agent (assistant or otherwise) interacts with the OpenClaw Gateway from inside it.

### Rule 1 — No systemd lifecycle from inside Gateway

> Any `systemctl restart|stop|kill` against `openclaw-gateway.service` MUST be issued by the user from an independent terminal — **never** via `tool=exec` from a Gateway-internal agent. This recreates the deadlock structure (agent→exec→systemctl→wait).

Rationale: the deadlock is structural; the only way to break it is to issue the lifecycle signal from outside the system that holds the exec session.

### Rule 2 — Agent scope = read-only probes + local file writes

> Inside the Gateway, an agent is restricted to: `pgrep`, `journalctl`, `openclaw sessions --json`, `openclaw gateway status --require-rpc`, `openclaw channels status --probe`, and local file operations (`mv`, `cp`, `edit`, `write`).

Out of scope: any systemd lifecycle, any service-control action that triggers a Gateway shutdown or restart, any action that would require Gateway itself to participate in its own restart.

### Rule 3 — Plugin re-enable uses hot-reload

> Plugin re-enable uses `openclaw config set <key> <value>` + `channels status --probe`. Hot-reload works for at least `plugins.entries.feishu.enabled`. Do **not** couple plugin re-enable with a Gateway restart.

Verified 2026-10-04: Feishu came back without `systemctl restart`, only via config set + probe.

### Rule 4 — Shell verification must echo variables before use

> Before any session-query command in a shell script, run `echo "$KEY"` (or equivalent) to confirm the variable holds the real value, not a literal placeholder like `'***'`. A masked identifier used as a shell-variable value produces "false success" — a non-existent session name returns `count: 0` without proving the target session is gone.

This rule was learned the hard way in this incident: agent reported "fixed" three times based on `KEY='***'` literal-string verifications, all of which returned meaningless zeros.

### Rule 5 — Long exec scripts get aborted; report honestly

> Multi-step exec scripts (≥6 sequential calls) get aborted by OpenClaw output-collection before completion. Either split into small single-purpose probes, or accept that mid-exec abortion means trailing steps did not run and report that honestly. Do not assume "I ran the script" implies "all commands inside it succeeded".

### Rule 6 — `daemon-reload` does not reload env vars into the running process

> `systemctl --user daemon-reload` reloads systemd unit configuration but does not push new environment variables into the already-running Gateway process. To apply env-var changes (e.g. in `litellm.conf`), a `systemctl --user restart openclaw-gateway` is required. `daemon-reload` alone is sufficient for changes to `Restart=`, `KillMode=`, etc. — but not for `Environment=`, `EnvironmentFile=`.
