## 2️⃣ 论文精选（paper，含 arXiv ID）

### 注入防御与对抗训练（本日最热赛道）
- **SecPO（2610.41998）**：现有最强防护模型 Meta-SecAlign 用 DPO 损失训练，在自适应注入下 ASR 仍逼近 100%，原因之一是 DPO 把模型锚定在**本身不安全的**未防御参考模型上。作者证明「注入不变 + 效用保持」的理想参考模型虽可逼近（其训练分布可访问），据此构造有理论依据的 SecPO 损失；同时实现 best@240 的强注入合成对抗训练管线。AT 相对 Meta-SecAlign 将三种 SOTA 自适应攻击的 ASR 降低 **1.5–14.5 倍**，SecPO 损失再降 **2.4–4.6 倍**。
- **ERASE（2610.41307）**：多模态间接注入把恶意指令嵌在**任务也需要**的媒体里，现有防御「挡住攻击却损伤任务效用」。ERASE 用 on-policy 自蒸馏，参考模型读的是「就地抹除注入区域」的同一媒体（模态适配的空白内容），周边内容保留；学生在自己的 rollout 上接受全分布 token 级反馈。图像/音频/视频、两个模型规模上观测 ASR 近零，效用接近未防御的干净输入；3B 音频受攻击输入准确率 **60.1% vs ARGUS 33.1%**，距干净输入仅 0.5 点，注入依赖度 6.26 → 0.0095。
- **SealCall（2610.41401）**：把「安全审计」外包给第三方，会把任务描述、调用参数、交互历史一并交出去——**安全检查本身成为隐私风险**。提出隐私保护审计范式，把「委托的审计计算」与「明文访问 + 执行权」分离，三域模型（可信表示构建 → 加密审计计算 → 可信决策与执行）经显式接口衔接；实例化为 CKKS 加密相似度计算 + 与被审计调用绑定的执行控制。
- **ANGLER / REEF（2610.41272）**：现有 web agent 评测多用固定攻击、且在**文本层**而非真实状态变更层评估攻击，系统性低估脆弱性。REEF 覆盖 9 个带验证器的真实站点（旅行/电商/生产力/媒体/通信），每个良性任务配 5 类攻击（用户层 + 环境层），用状态验证器驱动 ANGLER 的「近失手引导诱饵演化」自适应攻击框架。

### 检测、审计与「评测看不见什么」
- **检测器评测的盲区（2610.41803）**：审计 11 项检测评测发现，攻击/异常样本占比 **16%–86%**，无一项变动该比例，6 项**完全没做跨基准/跨来源测试**。2% 攻击率下 AUROC 0.879 的检测器精确率仅 **0.076**，且仅负样本构成变化就能把精确率在 0.039–0.117 间推动。工具覆盖率跌破约 50% 后**检测器排名直接反转**——未见过的工具映射到训练从未触及的输入。
- **工具调用轨迹的隐私侧信道（2610.41885）**：PrivacyTrace 基准（1,000 份合成用户画像 / 4,000 条轨迹 / 4 域 / 25 个真实 MCP 服务器）显示，仅凭协议合法的工具调用轨迹即可推断用户画像，攻击成功率 **26.25%**（先验猜测仅 17.97%）；工具参数与返回结果是主要证据，跨会话串联轨迹会进一步放大画像风险。
- **认知架构机制审计（2610.41604）**：把「全局工作空间」「心智理论」「主动推断」当卖点列出来的 agent 系统，名字在不代表机制在。提出可迁移的「声称—实现差距」验证方法：四问静态审计协议 + 行号证据 + 调用链追踪；对声称 25 项认知机制的系统预注册 11 项可证伪预测并执行干预，再在第二套独立系统的 IIT-phi 核心上以自设证伪标准复现协议。

### 工具、授权与恢复
- **跨接口授权（2610.41397）**：computer-use agent 同时经 GUI、命令行、API、脚本与 MCP 服务器行动——**策略决策可跨接口不变，可执行授权却不然**（换条路即可绕过中介、改掉安全相关默认值，或在授权状态已变后仍提交）。提出 profile-bounded 协议：枚举带副作用的路由与持久汇聚点、检查路由→汇聚点的强制切面、把请求归一为规范 effect、签发路由绑定 prepare ticket、commit 时再校验路由/effect/grant/trace/profile/清单/权威状态，且提交结果需汇聚点回执一致。在明确假设下证明 profile 有界细化、matched-effect 决策不变性、抗备选路由洗白与跨面重组、commit 时状态安全与回执支撑结果。参考 profile 登记 12 类 effect、5 个接口、60 条路由。
- **证据引导的恢复（2610.41453）**：工具超时会让 agent 面对「模糊结果 + 部分执行」——动作可能失败、已提交或仍在飞行，而其他工作流步骤已经完成。提出在已批准义务/供应方能力/公开证据兼容状态上的恢复：共享可容许性检查处理密钥过期、授权时序、依赖与残余效应，终局证书区分「真正达成目标」与「公开证据支撑的安全完成」。37 个任务的有限研究中，planning 与三个主动对照各认证 28 次完成、仅多花 4 个合成分；预注册的留出对比（58 配对单元 / 19 任务族）中，建议式规划认证 30 次 vs 证据提示式 9 次。
- **多工具召回的完备性与成本（2610.41905）**：检索器漏掉**任一**必需工具 agent 就失败，但工具召回几乎都只在单工具查询上构建与评测。比较六类检索结构（平铺词法/稠密、LLM 查询分解、LLM 导航层级、server-then-tool 匹配、依赖图、集合级训练召回器），在 345 条 AppWorld 与 103 个 MCP-Bench 任务（257 个 MCP 工具）上测 completeness@k。7,961 条 ToolRet 查询显示整体完备性混合了两个区间：单目标查询 k=10 时 0.58–0.67，**四目标以上查询仅 0.08–0.17**；单目标上的召回器排序在多目标上**反转**。
- **Verify–Backtrack Loop（2610.41564）**：长程任务的真正难点不是轨迹长度而是**恢复**——前置条件缺失时再试一个看似合理的动作几乎无用。ReAct 及后来的反思/自适应规划把恢复表达成自由文本，没有把终局目标、当前目标与失败来源连起来的显式控制状态。VBL 是免训练的 ReAct 扩展，把任务分解维护为有界目标栈，在目标激活/执行失败/状态实质变化时**联合校验两个视界**（当前目标是否贡献于终局目标、当前状态下是否可行），再由带类型的失败归因触发 Push/Pop/retry/Backtrack。

### MCP 生态
- **EvoMCP（2610.41479）**：MCP agent 的 SFT 长期在静态数据分布上做，无法适配学生能力演进，新暴露的弱点得不到充分处理。EvoMCP 建立 agent–数据互演化闭环：从 rollout 反馈评估既有能力与能力缺口以确定学习目标；任务演化把目标转成可执行任务（改写兼容已验证种子任务的指令与可观察环境状态，同时保持验证器一致）；轨迹演化用可复用技能救回失败的教师 rollout 并精化成功的；task–trajectory 对用于微调学生，被接受的任务再作为下一轮演化种子。

### 记忆
- **Accept Changes, Reject Attacks（2610.41056）**：记忆管理器有两类相反失败——**保留已过时的事实**（outdated）与**存入被植入的段落/注入指令**（poisoning）。既往工作分开研究二者，但它们要求相反的写入决策，因此**没有固定写入规则能同时处理**。形式化为记忆鲁棒性（处理二者且不在其他输入上变差），用 evidence-conditioned accuracy 度量（额外检查被选中记录是否包含答案所需的全部证据、且已更新、无攻击）。既有记忆系统与防御在测试集上**并不比未调优管理器更鲁棒**；用「围绕单条对话合成插入变更与攻击的 episode 微调管理器」的一发配方可显著改善。
- **KEEPER（2610.41482）**：递归文本记忆会把早期错误带进后续更新，而任务分单独不足以证明记忆可靠性。定义 **self-consistency bias**（入站记忆中已有错误断言的持续存在），在共享递归接口内沿「信息含量 × 更新敏感度」两轴比较四种辅助目标；奖励相关预测在离线 RL 前后都取得最高任务表现，优于联合监督；claim 级分析记录了「已有纠正性观察却仍持续错误」的轨迹。结论：应把错误持续率与有效信息保留率与任务结果一并评估。

### 多智能体与人机协同
- **When Should AI Agents Ask?（2610.41129）**：一个人同时盯多个 agent 时，某个 agent 该「问人」还是「自己找」不只取决于自身不确定性——**手上还有别的活的 agent 更早问反而更优**；而人先回答哪个问题取决于所有等待中的问题，**任何逐 agent 计算的排序都不是最优**。建立可搜索/可发问/可继续不依赖该信息的部分任务的随机模型并表述为动态规划，提出基于精确单任务与双任务子问题的 Pairwise Coordination Policy。
- **Ask on Demand（2610.41378）**：并行 agent 的有用发现常困在各自执行历史里；而共享机制往往在他人需求明朗**之前**就筛选/摘要，可能漏掉后来才变重要的细节。AOD 让 agent 在具体信息需求出现时**按需发起定向求助**：批准后从同伴执行历史检索相关证据、挑选合适同伴、生成定制化回答；用配对的团队续写训练轻量门控器决定求助是否值得。AppWorld 与 WebShop 上持续优于独立并行执行，且推理成本低于既有信息共享基线。
- **Renegotiable Options Fail（2610.40961）**：契约条款在「最大化自身利润」的前沿 LLM agent 之间是否同样保护投资？实验室实验中可重议期权把人类投资率从 41.5% 提到 67.2%。让 Claude Opus 5.5 与 GPT-6.1 Sol 在同结构一次性博弈、四种契约情形 + 参照价对照下各最大化本方利润：**结果完全符合博弈论预测**——可重议期权下无卖家做适配，排除该重议的期权下每个卖家都做。
- **Consensus Within, Competition Between（2610.41044）**：在通信不可靠时，多 agent 团队的任务分配该集中于单一 LLM 指挥者还是分布到自治 agent？简化的周界防御仿真中：共识团队突破率 **15%**，指挥者 **32%**，独立 agent **29%**；五种网络条件下只有有限通信半径会改变突破率（且拉高指挥者的）。共识团队中把出价计算权交给低成本 LLM，突破率上升 **38 个百分点**。

### 规划、技能与评估
- **TalentRL（2610.41143）**：多数系统从扁平 SkillBank 检索单个技能，却不显式建模支配其选择与使用的高层策略。TalentRL 提出对程序性记忆做层级路由：粗粒度「talent」代表技能使用的复发策略，细粒度技能提供可执行程序；策略模型为每个任务选一个 talent 指导执行，并在相似度召回中软性优先其关联技能；因任务结果同时取决于 talent 选择、召回的技能上下文与下游执行，终端奖励无法单独隔离路由决策的贡献。
- **CGAP（2610.41040）**：LLM 通常靠试错挑工具调用，无可执行计划保证。CGAP 改为推理「请求需要什么、工具提供什么」：把工具目录**确定性地编译成 PDDL 模型**，用 LLM 把请求转成目标，用经典规划器求解；因工具输出事先未知，模型是抽象的（追踪哪些输入可用而非其值）；执行期 LLM 补上抽象计划遗漏的实体特定调用，确定性检查拒绝任何破坏计划的调用，**每个参数都取自有引用来源**。
- **Subliminal RL（2610.41301）**：仅靠 GRPO + 语言模型评委（学生只从自身输出与一个评委的分数学习）就足以发生潜意识迁移：学生写虚构音节或数字，被做成偏好某动物的评委打分，学生的偏好即向该动物移动。48 个设计单元中 2 个未过效度门、17 个在 5% FDR 下确立了特质（含纯数字单元）；**仅移除两个评委之间的奖励差即消除迁移**。
- **Operon-S1（2610.41350）**：生物学长程 agent 对「约定、技能、错误、证据与停止」的判断都发生在干活的推理内部，无法被测量、替换或单独改进。Operon-S1 是 agent 的 System 1，把这些复现性判断作为闭合问题在 **13 个决策点**提出，并且只通过**不含答案的固定消息**行动，因此任何能答题的模型都可当评委。七个生命科学基准上，本地决策模型以 CPU 0.6 秒中位接管判断、无请求成本，六个基准中五个分数无可测变化。
- **ASTC（2610.41291）**：长程 agent 的交互上下文不断膨胀，抬成本且淹没关键决策证据；既有做法训练外部压缩器/上下文管理 agent 重写成更短的硬 token 序列，但外部选择未必对齐 LLM 演化中的表征且必然有损。ASTC 用 agent 内 soft token 做**免训练**压缩：借模型原生循环动态（常见混合 Gated Delta Network 注意力）判定已被吸收的信息，并将其作为可压缩 soft token 前传。
- **BlindToChange（2610.41435）**：agent 能广泛实时搜索，容易让人以为其输出已反映近期世界事件——但正确性取决于它是否搜索、搜什么。BrowseComp 等主流 agentic 搜索基准**显式告知要找什么**，无法暴露 agent 未识别自身待验证假设的失败；而大量真实请求只说最终信息需求（如一份行程），把「发现相关变更并计入其后果」的责任留给 agent。BlindToChange 以「显而易见的候选因近期真实事件已不再适用」的推荐类请求度量这种主动发现能力。
- **BABA-Bench（2610.41076）**：帮患者获取医疗的 agent 必须两件事都做到——**达成正确结果**与**遵守必要程序**（如分享病历前取得患者许可）。47 个交互世界全部由去标识化真实患者倡导案例构建、经专家倡导者审阅；每个世界中 agent 须找到隐藏信息并协调保险公司、诊所、供应商、药房与社区组织；引擎在 agent 每次动作的当下检查：是否有权限、是否有证据、动作是否被禁止。14 个前沿模型 × 3 次 × 47 世界 = 1,974 次运行；**agent 常能达成正确结果却未满足程序要求**。

### 权限、隐私与治理
- **Module Shadowing（2610.40716）**：agent 在不可信工作区操作时，最终报告与工作区状态**不足以可靠证明是否发生了执行**。提出从 agent 轨迹编码观察/推理/执行/响应行为、并与独立环境记录对齐以重建执行史、验证最终报告的评估框架。应用于 module shadowing（import 时本地文件顶替可信模块，无需任何对抗性提示即可执行不可信代码）：**90 次试验 / 15 个模型，直接 shadowing 载荷执行率 51%，间接 shadowing 87%；即便 agent 明确识别出 shadowing 机制也不保证阻止**。
- **MetaVul（2610.40721）**：用 LLM agent 自动检测漏洞时，准确率高度依赖 harness（LLM 周边的脚手架代码）。harness 通常固定且手写，限制对评估器反馈的适应，静态 harness 在一个数据集/模型上的改进也难以迁移。MetaVul 从结构化推理种子脚手架出发，用基于 workflow 的优化循环迭代精化 harness。
