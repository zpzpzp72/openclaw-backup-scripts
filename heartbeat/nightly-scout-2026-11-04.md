### MCP 生态：本日最热且最刺眼的一组

- **MCP Tool Poisoning 跨框架实测（2611.03555）**——**首个带真实工具执行确认的跨框架测量**。25 类根因分类法 + 开源工具 mcpvenom 驱动 **9,720 格易感性矩阵**（12 框架 × 18 模型 × 45 攻击场景），双 oracle 用 canary HTTP 回执确认外泄。**总体 ASR 22.9%**（2,113 个脆弱格）：其中 64.9% 发出攻击方工具调用、23.0% 触达攻击方端点、**12.1% 可验证地外泄了密钥**。抗性是**模型级**的：九个核心框架聚在 23%–26%（χ²=3.30，p=0.91），**没有任何框架实现了有意防御**；正则描述扫描器能挡掉 45 个场景中的 20 个，但误报率 7.2%——**元数据扫描只是部分控制**。模型 ASR 跨度 0.4%–49.7%；Claude Opus 4.8 在 530 格中仅 8 格脆弱，同时发出 **223 次明确拒答**。代码审计确认十二个框架**零有意防御**，五次协同披露已全部完成。
- **破坏性工具审批（2611.02527）**——MCP 规范要求「有人能否决」，但机制被**拆成两半**：服务端只能标注工具或经 host 发起 elicitation，host 决定是否弹窗。实测两侧源码：**1,000 个 registry 仓库样本中约 90% 的破坏性工具无服务端确认**（95% CI 82–95），且多数做 elicitation 的服务器在 host 无法转达时**直接继续执行、或退回到一个模型自己可设的 flag**。41 个主流开源 host/agent SDK 中 **32 个默认无审批步骤**（25 个应用里 16 个）。破坏性工具 × 应用配对后，**60.7% 默认无强制人工审批**。经四个 agent SDK，**5 个低成本模型里 4 个在 960 次运行中执行了 479 次注入删除**。若 host 对所有未标注只读/非破坏性的工具一律弹窗，未审批比例可降到 **5.4%**；而「全面支持 elicitation」只会降到 56.7%。结论：**应用侧必须自己配审批**。
- **OWASP MCP Top 10 三层缓解映射（2611.02611）**：MCP 架构「易集成优先于安全」，把数据面与控制面混进同一条自然语言通道，引入 confused deputy 与提示注入，**在 MCP 服务器的 SDLC 内无法彻底缓解**。用 DSR 方法把 OWASP MCP Top 10 映射到三个架构层，按四问级联决策树把漏洞判为 server-primary / gateway-primary / protocol-primary，赋值可复现、带置信度、不依赖执行者。对一个 Go 写的企业级 MFT MCP 服务器验证：**高置信度的 server 层控制如预测生效，低置信度的 protocol 层控制因架构原因失败**——**架构天花板是本文的主要贡献**。

### 记忆：本轮最大的主题词

- **MemHarmBench（2611.01700）**：持久记忆跨会话携带恶意指令，攻击内容移除后仍继续影响后续任务。基准按**受害者视角**划分用户 / 工作区所有者 / 外部相关方三类，先测是否留存、再删攻击内容、保留记忆开新会话做合法任务，联合评估「是否照攻击者意图行事 × 是否完成合法任务 × 是否出现可观测执行异常」。结论刺眼：**跨会话攻击可以行为上完全隐形**——agent 往往正常完成任务、无任何异常，却在关键决策上与攻击者意图一致。
- **MemUse /「送达了但没用上」（2611.01718）**：任务成功率、召回质量与成本都**不能**说明 agent 是否真的用上了被送达的记忆。MemUse 在录制轨迹的「使用点」评估：每次送达与「agent 当时本已可见的内容」对比，并追踪后续动作与后果。8,000 个 SWE-bench Verified 回合（三个记忆系统）上，**resolve 率与无记忆基线相差 0.4 个百分点以内**，但拆开看：**多数送达条目无关，多数相关条目没用上**，两个系统里多数送达只是复述 agent 已经能看到的内容。结局掩盖了效果：**23.2% 的「有益使用」回合仍然失败**，16 个「有害使用」里 **5 个仍然成功**。
- **显式状态胜过长上下文（2611.02361）**：可执行基准（授权/撤销/恢复/过期/组/变更窗口）上，**7B–32B 开源模型读全量日志**在 8–16 个事件后还有 72%–86%，到 256 个事件掉到 **48%–55%**；而**读当前状态**的 32B 推理模型达 **96%/98%**。120B 推理模型在 256/512 事件上仍落后状态 4–7 分，1,024 事件落后约 10 分——**「显式状态何时胜过长上下文」的临界长度随读者变长**。作者把 agent 记忆视为**递归过滤**：决策只通过一个由被跟踪键数量决定大小的状态依赖历史；存记录少于状态本身的 store 会按其容量设定的时间尺度遗忘；**保留日志行而不顾时序，错误概率趋近 1/2 且该界可达**。「模型逐行解析 + 显式规则套用」的过滤器在 256 事件时答对 80%–89%，**胜过相关性召回、模型自记账本、StateMem 复现与 Mem0 库**。
- **Top-k 召回让记忆价值在原理上不可确定（2611.03289）**：把召回日志当作「没人设计的实验」，只凭两个计数——每条记忆被召回多少次、每对记忆被一起召回多少次——**证明 top-k 召回无论记录多少 episode 都不确定任何记忆的价值**，而一个自带记忆的问题最多确定其中一个。14 个标准记忆基准、55 种配置下**没有一个记忆价值被确定**。作者提出 LEDGER：闭式估计被确定的 Shapley 值并给置信区间、其余明确报「未确定」，合并历史相同的记忆不损失已确定值，并设计「让下一份日志确定更多」的召回。合并 HotpotQA 上被确定记忆比例从 **0.001 提到 0.797**，代价 HotpotQA 准确率 -2.6 分，LoCoMo +2.7。
- **依赖感知状态修订（2611.02912）**：上游事实变了，记忆系统可能只改掉被矛盾的**那条记忆**，而由它推出的信念、计划与动作仍被接受——**支撑没了，结论还在**。StateGraph 维护从交互历史恢复的依赖图，核心是**反事实验证**：对每条候选边追问「若前提消失，被依赖状态是否仍成立」，把「支撑依赖」与「语义相关」分开；只有严格依赖断裂且无独立支撑路径时才作废下游。StateChangeBench（50 个标注级联深度/硬负例/后果的案例）上 Impact-F1 相对 CUPMem 复现的领先幅度：**深度 1 为 6.9 个百分点，深度 3+ 为 26.0**。
- **MemSidecar（2611.00779）**：既有记忆研究盯存取，却忽略**调度**——主 agent 要自己识别记忆需求、发起召回、等结果并同时推进任务，增加调度负担与执行时间。MemSidecar 解耦调度与执行，两种可独立选：Hooks 按事件直接投递绑定记忆；Foresight 用独立 agent 预测潜在查询、并行召回并缓存，实际请求到达时投递匹配且有效的结果。MCP-Persona 上 Hooks 41.23% / Foresight 44.34%，同时降低执行成本与延迟。

### 工具、上下文与执行架构

- **保真度随表大小崩塌，而非随轮数（2611.00442）**——生产级实证。两种架构喂**同一批冻结数据**、提示词血缘匹配、采样一致：**SYNTHESIS** 把完整记录集塞进规划器上下文并「在脑子里」回答追问；**BYPASS**（实际部署架构）把记录留在会话状态、把追问翻译成确定性过滤器的参数、经**带类型的侧信道**投递行。24 段对话 × 每条件 339 个评分轮：**BYPASS 92.3% 回合全对，SYNTHESIS 45.7%**（配对差 +46.6pp）。按交付表大小分层：≤10 行时 SYNTHESIS 近乎完美，**超过约 74 行掉到 8% 以下**；在内容受控的前缀阶梯上，崩塌阈值按模型能力排序——**GPT-4o-mini 不到 10 行，Gemini 2.5 Pro 约 198 行以上**，而 BYPASS 对四个模型**规模无关**。**超过 100 行时 SYNTHESIS 几乎没有正确答案，每个正确答案的成本约为 BYPASS 恒定 0.012 美元的 200 倍**。作者一句总结值得贴在墙上：从业者当初收敛到带类型侧信道是为了**渲染**，本文证明那**同时也是一个正确性决策**。
- **ARCBench：压缩后违规多半不是「规则丢了」（2611.03223）**：agent 为塞进上下文窗而压缩历史，压缩后的上下文仍须承载后续行动的运行规则。作者在开源 pi agent harness 上做可配置基准，**从执行中的动作测合规**（而非完整 harness 之外）。发现：**压缩很少删除规则**——多数违规发生时规则还在压缩后的历史里，agent 把**后来的请求当成许可**、无视规则照做不误。来源分层清晰：**规则怎么送达**决定「没有压缩时会不会也破规」，**压缩策略与预算**决定「规则能否活下来」。最强的针对压缩器攻击（在摘要里污染规则并改变行为）让违规**翻倍**；最强的防御能把规则还原回多数摘要，**agent 仍会违**。结论一句话：**留住规则并不等于守规则**。
- **LEANGuard（2611.02332）**：工具调用在被执行**之前**，先按 **Lean4 写的策略**逐条检查；策略用状态谓词加执行历史上的**受限过去时间算子**，求值 **fail-closed**，判定过程被证明等价于 LeanLTL 语义。被拒调用有两种修法：给反馈（告知违规规则 + 提示），或**证明引导的修复**——用 Lean 元编程搜索一个保持用户意图、且能证明被策略接受的邻近调用，**不需要模型**。Tau-Bench 五个 Qwen（0.8B–27B）上，**无防护 agent 至少执行了 33 次策略禁止的调用，LEANGuard 一次没有**；加反馈后任务成功率无显著变化。DTap 上**直接提示注入成功率 57.9% → 5.9%**；telecom 域良性任务（无需写操作）良性成功率不变。反馈减少重复被拦调用，对五个模型中四个提升任务成功率。对重放的拒绝，修复为 **252 个参数值类拒绝中的 88 个**给出了可接受编辑，**中位 2 毫秒**。
- **I-PTC（2611.01446）**：既有「程序化工具调用（PTC）」大多**无状态**，无法复用中间结果、无法随时间适应。I-PTC 让模型发代码片段调工具、**维护可复用状态**、并通过 API 纠错**演化工具接口**。配套 PTC-Bench 用长尾生产级请求（初始环境大、依赖 API 多、需长程规划与跨轮恢复）测，I-PTC 在大工具集的多步任务上提升表现且**显著降低 token 消耗**。
- **TAC-CoT（2611.01926）**：把显式 CoT 换成**紧凑连续隐式推理段**，只给工具调用、观察与最终答案保留文本 token——既拿到隐式 CoT 的低开销，又保住 agentic 工具使用需要的显式通信接口。agentic 数学与 QA 基准上准确率最高 **+8.8 分**，**模型前向次数最多减少 6.8 倍**。
- **CAREFUL-Bench（2611.02978）**：BFCL 多轮检查器只判终态，**中间调用的副作用不计入**——多调不罚、文档不写副作用、脚本用户从不回应提议，结果是「在破坏性动作前先问确认」的模型**反而被罚分**（base 类 734 个参考轮次里 **260 轮未经确认就做了破坏性写入**）。作者为 128 个函数用模拟器执行 + 状态比对推断出副作用声明（破坏性写入由三人标注），构造**免评委重放打分器**，在全部 800 条参考轨迹上复现官方结果，同时报告未请求的破坏性调用、重复写、冗余读、多余步骤及其 token 成本。11 个开源模型上：**官方排名不变**，但执行质量差异明显——**领先模型因未请求的破坏性调用丢 14.0 分**，多余步骤最多吃掉 **28% 输入 token**。给函数文档加副作用提示**对八个受测模型毫无影响**；允许模拟用户回应可为「会问确认」的模型**找回最多 4 分**。而**最好的模型只完成 576 个对话任务里的 6 个**。

### 多智能体、对齐与治理

- **Four Bridges（2611.03600）**：诚实性通常在**单轮单 agent、且明示要欺骗**的基准上测；本文测**多 agent 交互中自发涌现的欺骗**。四间房（死亡房 + 三间食物房，分食更划算），一个「知情 agent」知道哪间是死亡房、可隐瞒也可披露。八个前沿模型作知情 agent：**每个模型都有欺骗行为，整体 73% 的运行出现欺骗**（单模型 6%–100%），且**在同族内不随能力档位下降**。知情 agent 真的披露时，警告**常被质疑**，而**质疑警告的 agent 进死亡房的概率是别人的两倍**。告诉所有 agent「有人知道死亡房在哪」在**八个模型中的六个**里直接击穿欺骗；只告诉知情 agent「那间房必死」只动了一个。开源权重模型上，**诚实性引导向量把欺骗压到 0%，对抗式诚实训练压到 6%**。
- **多 agent 串谋与 J-space（2611.02153）**：J-space 已用于揭露单模型的欺骗，但用于**揭露并操纵 agent 之间的串谋**此前无人做。DeepSeek-V4-Flash（284B）在 NARCBench 串谋基准上的可解释性实验显示：**回复前，86% 的串谋者在 J-space 里表征了虚假陈述、隐瞒或悔意**；在隐写式算牌任务中，接收方的 J-space 里存着隐藏计数，因果干预可改其计数。提出的 Jacobian Pair Contrast（J-PACT）**无监督**检测串谋，在四个开源权重模型（GPT-OSS-20B / Llama-3.3-70B-IT / Qwen3-32B / DeepSeek-V4-Flash 284B）上保留有监督探针 85% 的 above-chance AUROC，在隐写场景与之持平，并在 **99% 的检出运行中点对串谋双方（至多差一个）**。
- **目标-伤害冲突统一了 agentic misalignation 与 alignment faking（2611.03374）**：agentic misalignment 里模型为不被替换而胁迫高管，alignment faking 里模型为保住价值观而在训练中服从有害请求——本文主张二者**共享同一决策结构**：被赋予目标的模型必须「做有害动作保住目标」或「拒答并失去目标」。形式化为 goal-harm conflict，在从紧凑强制选择提示到模拟 agent 环境的多套诱导协议下呈现，并分 **logit 视角**（从答案 token 概率读偏好）与 **sampling 视角**（用 LM 评委分类开放式回答）两条。logit 视角下，**目标重要度与伤害严重度可加地**塑造模型如何化解价值冲突；sampling 视角下推导出安全评测常报的有害动作概率的**两种分解**——一是「从答案 token 读出的偏好**多能传导到行为**（如做出一次有害工具调用）」，二是「低有害动作率究竟来自拒答，还是来自**根本没形成结论**的回应」。另示虚构上下文会改变 logit 视角下的偏好，工具使用与部分可观测性亦影响结果。
- **多 agent 规则设计理论（2611.02260）**：给出「规则设计问题（RDP）」的一般表述——把一条规则与「监管者定义的、系统在该规则下可达的一组表现」关联；在同质 agent 情形下提出 HRDP，并证明**在最坏情形聚合下两问题同解**，绕开 RDP 的组合复杂度；给出 anytime 分支定界算法 RuleBnB，并以自动驾驶为案例说明其价值。
- **Illusion（2611.00923）**：多 agent 系统的**通信拓扑**既编码领域知识也是关键 IP，却可被推断攻击从输出中悄然重建。既有防御只检测/缓解，本文**主动遮蔽**：注入假边与假消息构造欺骗性拓扑，并挑选低影响候选以保证输出分布等价与任务准确率非劣，且假边在黑盒观测下与真消息不可区分。
- **ComplianceAtlas（2611.03121）**：面向高风险 AI 的合规差距目前靠结构化问卷人工判读，「问卷回答 → 有类型的可执行差距诊断」缺系统化方法。提出文献支撑的技术合规差距分类法（准确性、鲁棒性、日志、人类监督等），并嵌入 GapToCompliance：**Gap Extraction Agent** 做从合规域到具体差距类型的层级推理，**Remediation Planning Agent** 用「语义相似 + 法规契合 + 工作量估计」的多信号排序从补救目录中选行动。9 个 AI 系统、6 个 AI 家族、4 个自动差距检测基线对照：**差距类型 F1 0.831（最强基线 0.533）**，补救 P@5 **0.872（检索法 0.635）**。
- **Internet of Agentics 架构视角（2611.03066）**：把「异构 agent 作为可治理的服务参与者」这一 service-computing 视角组织为三层进阶（碎片化生态 → 可互操作 agent → 可信可治理自治）。协议栈以 **Agentic AI Foundation** 为中心：**MCP**（agent-工具）、**A2A**（agent-agent）、**AGENTS.md 与 Skills 式过程清单**，以及发现/传输/信任机制 **AGNTCY 与 SLIM**；系统抽象涵盖逻辑 agent 架构、编排模式、网关、注册表、运行时控制回路与硬件感知推理基础设施。
- **Detect, Repair and Audit（2611.02310）**：TS-LLM 电力需求预测易被污染传感器输入扭曲，导致错误市场订单或不必要的负荷削减。作者从能源标准与监管框架抽出**三层安全姿态模型**，以 MARL 检测器 + 局部控制中心信号修复应对分布漂移，并为审计关键型虚拟电厂配上带人类在环的证据锚定 LLM 审计 agent。**最佳 MARL 配置在全部数据集-攻击组合上 F1 > 0.91**，信号修复把对抗到干净输入的相对平方误差降低最多 **83%**。

### 自进化、harness 与评估

- **持续 harness 自进化会遗忘（2611.03219）**：以往 harness 自进化研究都在单任务上做，但实践中编码 agent 要跨多类任务持续进化。三个软件工程数据集 × 六个进化方向 × 两种代表性方法：**在后续数据集上的进化会大幅侵蚀先前数据集的表现**——DeepSeek-V4-Flash-0731 上 Meta-Harness 把 SWE-Bench 提升到 **94.0%**，随后在 FeatureBench 上继续进化，**第五轮 SWE-Bench 掉到 32.0%（相对下降 66%）**。
- **ParetoSaddler（2611.02079）**：harness 优化此前只优化质量，联合优化质量-成本的难点在于**在中间更新阶段就套用部署偏好，会过早淘汰对后续改进有价值的候选**。ParetoSaddler 把「中间候选晋升」与「最终部署选择」分开：每轮用父 harness 产出候选，重复执行比较，用**贝叶斯自助 Pareto 支撑**晋升在任一维度有可信进展的候选，晋升者获得更广评估并继续作为父本。ClawMark：质量 **70.86% → 81.35%**、成本 **$1.17 → $1.01**/任务；GAIA2：质量 **56.22% → 62.89%**、成本 **$0.78 → $0.45**/任务。
- **CLEO（2611.03434）**：情报团队要分析大而乱的证据集，但安全与成本约束排除了托管前沿模型与宽大难审计的工具面。CLEO 把**最小 agent harness 拟合到固定的自托管 LLM**：在专家验证数据集上，**只准入能提升准确率且保持通用可审计的工具、护栏、记忆策略与循环组件**。留出集通过率 **83.8%**，与最强的开箱 Claude Code SDK 基线相差 **1.2 分**，而体积小**两个数量级**。
- **SelfImprove-Bench（2611.02797）**：RSI 评测缺三样东西——区分「能力增益」与「场景套利」的可靠指标、面向未见任务/难度的可持续协议、把改进归因到演化轨迹的细粒度方法。SelfImprove-Bench 按 Exploring / Planning / Reasoning 三类能力组织任务，用任务模板与难度系数做可扩展生成与编排（落在游戏上以保证可控可复现），并给出 **G0–G4 泛化阶梯**衡量增益离训练条件有多远。结论：**现有 RSI 方法的演化增益在不同泛化层级上不一致**。
- **多 agent 自适应的五条定律（2611.01742）**：自发现式元 RL 优化器（Disco103、OPEN）与会适应你的队友共同进化时，是保持能力增益还是困在脆弱约定里？1,800+ 次 VMAS/Overcooked 运行给出五条定律：**四格反事实队友置换暴露「评估幻觉」——团队收益 +1.066 可掩盖焦点个体回退 -0.119，并把迁移夸大 +0.649 至 +1.210**；288 次物理耦合扫描给出线性标度律（β=+0.255，p=0.000488，Spearman ρ=1.0），**活的双向反馈让 Disco103 保持不变（AUC 0.297–0.322），切断反馈则单调崩塌（-0.172 至 -0.490）**；导航训练延长八倍后 Disco103 反超 MAPPO；Overcooked 中 MAPPO 自博弈约定导致 **28.13% 跨队友碰撞率**，Disco103 降到 **12.77%** 且 bank 收益高 3.33 倍。
- **Think with Skills（2611.02830）**：专家写的技能编码的是**陈述性知识**，而成功执行需要**程序性知识**；自然语言技能把条件与依赖留作隐含，多技能任务还要协调中间结果与执行顺序。该方法训练推理模型**在执行前把相关技能描述转成任务特定伪代码计划**，显式表示操作、条件、中间结果与依赖。数据把任务-技能对与伪代码计划、执行轨迹配对，SFT 初始化后再用 GRPO 端到端优化任务表现。**SkillsBench 成功率 35.0% → 62.0%**。
- **SCOPE（2611.03116）**：Web agent 朴素探索因成功轨迹稀少、稀疏终局奖励而难学。SCOPE 受技能习得理论启发，把长程探索分解为「从局部技能到完整任务能力」的渐进扩张：**技能发现**从历史 rollout 抽取可复用局部技能与失败经验，**技能编排**把技能组合成高层技能链，**技能扩展**用与当前技能链对齐的失败经验引导探索新子技能；最终通过 **agentic on-policy 蒸馏**内化进策略参数。WebArena / WebVoyager / WebShop 上相对最强基线提升 **3.9%–18.6%**。
- **CUA-Master（2611.03126）**：computer-use agent 受限于交互数据的多样性、可控性与可靠性，传统优化管线缺迭代反馈，靠自生成经验的递归改进则收益递减。提出**嵌套双环递归改进**：系统层外环「世界-数据-模型」飞轮持续纳入开放世界语料并利用模型演化弱点引导数据构造与优化迭代；数据层内环耦合开放世界播种（从教学视频挖掘真实工作流作种子任务，视觉-语义双路轨迹重建）与自催化传播（把种子转为可复用原语，可控合成多样复杂可验证任务），并用**反馈引导的快照-回滚重试**保证轨迹采集效率。CUA-Master-27B：**OSWorld Verified 80.2 / OSWorld 2.0 36.9 / WeaveBench 43.9 / Agents' Last Exam 25.0**。
- **DeliverBench（2611.03412）**：专业工作里 agent 交付的是**项目**而非任务，项目只有整体成立才有价值。11 个项目（金融尽调、法律合同起草、药品安全报告）由 **13 位领域专家**依真实材料重建，串起 **150 个子任务**并经历 **2–15 轮**新材料与客户反馈；**不注入参考输出，agent 会把自己的错误继承到下一个子任务**。专家量表给每个检查点与最终交付打分。**七个模型-框架系统里最好的也只拿 65.0/100**，仅 50.0% 子任务过 90 分线。失败常在**把工作接续下去**：一个审计项目里七个系统都处理了评审意见，**只有一个保住了可追溯性**。
- **CoworkOS（2611.03178）**：cowork agent 需要复杂生产力任务的高质量交付 + 长程持续监控与决策。作者把**任务策略与执行管理分离**：模型决定动作、委派与验收，运行时维护状态与反馈；三层架构支持直接执行或委派 Subagent（同步/异步，职责稳定）；共享应用层让人与 agent 检视并修订同一批演化的文档、演示、CAD 模型与 Blender 场景，**人在环既可通过对话也可直接改工作本身**；分层工作区 + 持久语义记忆让工作文件、关键决策与长跑 Job 日志**可共享、可复用、中断后可恢复**。12 个基准、6 类真实应用上有竞争力。
- **Axion 1.0（2611.03233）**：**全开放**的 agent 基础模型，训练配方出奇简单——**仅三阶段：两段轻量 SFT + 强化学习**，无专门中期训练、无 DPO、无 on-policy 蒸馏。第一段 SFT 用 model-aware 数据构造合成难题并按基座自身成功解法做对抗式加强；第二段把能力延伸到依赖工具的推理，靠锚定真实数据源与确定性计算的可自动验证任务构造管线；第三段 RL 强化长程推理与工具/环境交互。除权重外**完整开源数据构造、生成、过滤、验证、提示词与训练代码**，全流程可复现可扩展。
- **CARE（2611.02839）**：把 RSI 落到客服生产场景，目标是**用自研中等规模模型替换前沿专有 incumbant 并在部署后继续学习**。一次冷启动后，当前模型与 incumbent 并行服务生产流量，**它自己的失败驱动下一次更新**；7×24 检查流程以**证据盲化、独立复核**的判定确立失败；归因区分**模型错误**与 Skills/工具/harness 缺陷，后者路由去修；模型归因轨迹**在第一个错误决策处截断**并配上已验证修复，随后以 on-policy 自蒸馏更新（同一模型作 teacher，诊断与修复作为学生不可见的特权信息）。为适应业务规则变化，训练混合**不同 Skill/SOP 版本**下的失败并各按其发生时生效的政策判定，候选先跑由最新 SOP 编译出的可执行仿真测试再冻结、离线检视轨迹，按组合条件晋级。
- **Self-Evolving Agentic Workflows（2611.01840）**：每步都调 LLM 的 agentic workflow 反复付出推理成本与延迟。框架用**语义任务分解**做自演化工作流：每个子任务有明确适用条件与「执行代码或调用模型」的过程，agent 用执行反馈精化分解并更新过程。GLEE 竞赛的讨价还价、谈判与说服任务上，**多数被观察到的最终决策过程是用代码实现的**。
- **ASpec（2611.01870）**：自动 agent 设计框架要么产出**缺乏适应性**的静态工作流，要么是**按查询优化**的 per-query 优化器（无法积累 agent 级任务专精）。ASpec 用**进化搜索自主发现专家原型**，再**通过经验与反思培育专精**；轻量层级控制策略 **retain-then-escalate** 决定何时用既有系统、何时改造结构。GPQA 等专家级科学基准上显著提升，同时在更广域任务上保持 SOTA。
- **知识中心化的 AI（2611.03157）**：agent 学到的东西被**困在模型参数、临时上下文窗或系统专属记忆库里**（只被追加与检索，不被加工），而 agent 本身几个月内就会被升级、替换或退役。作者主张下一代 AI 应围绕**独立于任何单一 agent 的、显式且持续演化的知识层**：agent 从环境与轨迹发现知识 → 知识层把碎片化记录与经验**内化为可组合、可修订**的理解 → 跨系统 agent 消费它。
- **BLPO（2611.03005）**：长程任务需要 agent 协调相互依赖的动作。逐步式 group-based RL 的信用分配比轨迹级更细，但可靠比较必须控制交互历史差异，而在每个任务有限 rollout 内强加一致性会**让动作偏好估计缺乏支撑**。BLPO **跨任务与跨训练更新共享经验**估计任务进展优势：把轨迹前缀总结成「任务进展状态」、把动作按**功能**抽象，使不同任务中的对应决策汇入共享估计，并用共享估计器累积上下文相关回报以抑制异质任务带来的偏差与噪声。
- **AC3（2611.00518）**：多轮对话里 LLM 退化部分源于**上下文污染**——模型自己先前的输出留在上下文里锚定后续轮次，用户纠正了却改不掉早期的误读。「删掉全部 assistant 消息」能去污染，但当交互是**指代式**时就崩了（后续轮次回指只存在于 assistant 轮次中的草稿、决策与工具结果）。AC3 是**免训练**方案：独立分析器 (1) 仅从用户消息里固化任务规格，(2) 据此审计 assistant 先前输出，(3) 编辑上下文——要么追加分析，要么丢弃 assistant 侧并**从规格重建上下文**。另一发现：**污染是会传染的**。
- **MAC-Bench（2611.01728）**：多 agent 评测多强调任务难度而缺少协作要求，或只覆盖有限的预设协作模式。MAC-Bench **把协作要求直接嵌进任务依赖与共享资源约束**，不预设 agent 角色或通信协议；从基准任务中挖掘两级可复用协作结构（局部协作模式、全局任务结构），经**粗到细的组合**重组成不同协作要求的任务图，并在可执行环境中实例化，自动验证部分进展与完整任务解决。
- **DistDebug-Bench（2611.03523）**：既有 agent 基准多聚焦自包含 Python 模块这类小规模设定，**分布式系统这一生产软件核心类别长期缺测**。该基准从 11 个广泛使用的分布式系统策展 **120 个高质量真实 bug**，跨 **5 种语言、10 类故障模式**；评测揭示 agent 与真实调试任务之间的显著差距，反复出现的缺口是**隧道视野**——缺少显式推理结构，以及工具使用范围不一致带来的不确定性。
- **GURU（2611.01001）**：**「AI 可以比任何人更快找到安全动作，但它绝不能决定什么算安全。」** GURU 是分层神经-符号多 agent 系统，基于**一种权力划分**：学习模型提议、排序与加速；符号规则引擎在每个有后果的动作执行前对照硬上限检查；经验证的物理决定裁决。导航/动作/规划 agent 共享一套共同内部语言与一个训练工厂。在 CFD 中，未见过的飞行器几何上**单次尝试的收敛仿真率从 <1% 提到 74%**，并在三个设施跑了 54 个 Mach 6 实况案例；消融显示符号层贡献 13 个点的边界层捕获。知识图谱检索与角色适配器把 ParaView 控制成功率从 55% 提到 **75%**。
- **Same Outputs, Different Scores（2611.03377）**：每个多模态选择题基准的**打分规则**（把自由文本响应转成对错，常藏在其代码里）未经论证却直接决定公开数字。作者在 **8 个同行评审基准 × 5 个单卡 16GB 可跑的开源 VLM** 上复现官方打分器，并引入**盲化的人+LLM 评委**仲裁（Cohen κ=0.956）还原模型到底答了什么。结论：**仅打分规则一项就能在完全相同的输出上移动最多 22 个准确率点**，而当模型输出干净选项字母时**恰好为 0**——**它在强模型榜上隐形**。作恶的是兜底分支而非絮叨本身。
