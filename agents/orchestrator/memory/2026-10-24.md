# 2026-10-24 Orchestrator NightOps / 故障修复

## Signal
Orchestrator NightOps 连续失败 5 次（10-22 ~ 10-23），错误 "All models failed (3): minimax fetch timeout | longcat timeout | ollama ECONNREFUSED"。
非 Orchestrator 专属 — Scout/Life/Coder/Main NightOps、news-digest、4 路夜间 NightOps 全部同一时刻同样失败。

## Root Cause（3 层，全部已定位并修复）
1. **代理地址错误（P0，根因）**
   - 代理实际在 WSL host `172.18.160.1:25017`（.bashrc alias proxyon 正确）
   - 但脚本硬编码 `127.0.0.1:25017` → WSL2 内 localhost 不通 → Connection refused / ENETUNREACH
   - 修复：`~/.openclaw/scripts/openclaw_news_digest.py`（3 处）、`run_news_digest.sh`（2 处）全部改 `172.18.160.1:25017`
   - 备份：*.bak.2026-10-24
2. **ollama provider baseUrl 指向 localhost（P0）**
   - `127.0.0.1:11434` 无监听；实际 ollama 在 `172.18.160.1:11434`（200 OK，qwen3.6:27b 已拉取）
   - 修复：openclaw.json `models.providers.ollama.baseUrl` → `http://172.18.160.1:11434/v1`
   - 已 hot reload 生效
3. **fallback 链含死链（P1）**
   - `litellm/MiniMax-M2.7` @ 192.168.31.231:4000 返回 `no_db_connection`（LiteLLM 后端 DB 挂）
   - 已从 fallback 链移除 → `['ollama/qwen3.6:27b', 'longcat/LongCat-2.0']`

## 补充根因（04:50 窗口实况）
- 10-24 04:50 Orchestrator NightOps 仍 error，但错误已变为 `agent run aborted | OPENCLAW_DIRECT_ABORT`
- 真实原因：**MiniMax Token Plan 额度耗尽 429**（`已达到 Token Plan 用量上限 (2056)`），今日 02 点起爆发 382 次
  - 分布：02点 151 次 / 03点 19 次 / 04点 211 次 / 05点 1 次
  - 与 proxy 故障是**两个独立问题**，前者的 fallback 链因 ollama 指向 localhost 而无法接管
- 排查 provider 凭证现状：
  - `minimax` — 有 key（config/minimax-api.env），额度为 **burst 型**，高峰耗尽
  - `siliconflow` — env 里的 key 已失效（`Token is invalid.` 30014），**整条 provider 不可用**
  - `litellm@NAS` — `no_db_connection`，**整条 provider 不可用**
  - `longcat` — 配置里无 key，实测 401，**不可用**
  - `openrouter` — 402 余额耗尽，**不可用**
  - `ollama` — ✅ 唯一可用（本地 GPU）
- 结论：**真实可用 fallback 只有本地 ollama**，此前因 baseUrl 指错而形同虚设
