## 2️⃣ 论文精选（paper，含 arXiv ID）

### MCP 与工具使用

- **LIBRA（2611.05445）**：把「扁平工具目录」变成**可执行工具库**。多数检索器按请求相似度逐个排序工具，多工具任务里会捞到「目标匹配工具」却漏掉**流程所需的前置工具**。LIBRA 让 LLM 为每个工具提出契约（候选调用、可复用输出、状态变更、成功条件），再**在沙箱里实测这些组合**，只保留运行时站得住的关系。**无需依赖标注、无需工具使用轨迹、无需任务特定训练**，且在查询到来之前就构建好。AppWorld / BFCL / SciToolEval 上，one-shot Recall 与 NDCG 相对同一稠密检索器平均 **+7.9 / +3.7 pp**；在 ToolReAGt 内经十轮检索迭代仍 **+4.5 / +2.9 pp**。
- **ArcRAG（2611.06481）**：问「检索策略换一种构图方式还灵不灵」。GraphRAG 的检索策略通常是围绕**自己构图流水线产出的结构**设计的，换构图的稳健性很少被测。ArcRAG 在**推理期**为当前问题诱导出一张**局部图接口**（问题点名实体可达的节点标签、关系描述子、属性键），据此规划多跳遍历并以 Cypher 执行与修复；MuSiQue / HotpotQA / TriviaQA 各建两套图（schema 引导的类型化图 vs 开放信息抽取的无类型图），检索配置保持不变。结论：**检索不必与图共同设计**，查询期接口诱导能让「与构图无关」的检索器在换构后依然有效。
- **EviSeek（2611.06434）**：具身主动信息获取的核心难点是**无目的交互**——动作看似合理，却没说明它要揭示什么证据；动作计划和累积历史都把交互的**信息目的**留成隐含。EviSeek 把「由问题推导出的证据需求」显式化为获取目标，把观察条件化动作与**选择性保留的证据**对齐到 agent 要找的信息上。3,436 道 ESI-Bench 题上比单模型 agent 提升 **7.1 pp（Qwen3-VL-32B）/ 3.7 pp（Gemini 3.1 Pro）**，同时视觉支撑加权准确率上升、**平均 token 反而下降**。
- **ZETA / Route First, See Later（2611.06760）**：科学图像分析要 agent 在描述、检测、计数、分割之间选能力，现有多工具架构**把意图理解与视觉执行混在一起**，于是「路由错」和「感知错」两种失效无法区分，高风险科学自动化因此不可审计。ZETA 先解析科学意图、再调视觉工具，并把**测量当作由显式几何支撑的确定性操作**而非生成式输出，从而把路由正确性与下游执行作为**可独立评估的两种失效模式**。51 道科学意图零样本题上，Qwen 3.8 的分割路由准确率 **6.2% → 75.0%**。
- **GraphRail（2611.06662）**：检索增强系统常常**答案对、过程错**。可靠审计要问三件事：证据 D 是否覆盖问题 Q、推理 T 是否回应 Q、T 是否被 D 支撑。GraphRail 把需求、证据与推理表示成结构化断言并**互相比对，不生成式评委、不用标准答案**。三个多跳 QA 基准 × 三种推理框架上，错误召回优于生成式验证器，且在随机抽取扰动下稳定；其诊断还能反过来引导在线推理。
- **MCP-Eco（2611.06897）**：研究 MCP 生态需要把**服务器接口、配置它的项目、它们的开发活动**连起来，而这些信息散在目录、包注册表、配置文件与仓库历史里。MCP-Eco 做成关系型数据集，冻结版含 **19 张 Parquet 表、16,880,899 条记录**，覆盖 78,302 个候选服务器项目、16,165 个候选消费仓库、9,200 条配置声明（其中 5,975 条解析出 5,138 个「仓库-服务器」对），并附工具/资源/提示描述、声明依赖与 PR/评审/issue/commit 等开发记录，且用 provenance 字段区分「目录自报能力」与「实际探测所见」。

### 多智能体：协调、越权与韧性

- **TandemBench（2611.05827）**：决策模型在多智能体协作里决定**怎么分工、怎么交换资源、怎么并行**，但「团队方案选得对」和「能否判断给出的选项里已经含有最优解」是两件事。1,200 道多智能体烹饪场景题，参考答案由**执行 + 精确搜索**确定。40 个原生决策模型 + 10 个通用语言模型：**最好的原生决策模型决策准确率仅 62.50%**，而在「最优性验证」上**接近随机**；配对实验显示有些模型**无论是否已提供最优方案都报告存在更优替代**。结论：单看方案决策准确率，会掩盖判断「选项里是否已含最优解」的系统性错误。
- **MA-Mesh（2611.06389）**：现有多智能体系统**几乎不显式建模韧性**，靠临时纠错，限制了系统性的运行时鲁棒性管理。MA-Mesh 在协作模式之上生成「韧性感知」系统规格并合成为可执行的多智能体策略代码，引入两个自愈机制：**跨 agent 反思**（不仅评估自己、也评估同伴表现，据此调整行为并集体修正策略）与**基于角色的故障转移**（子任务失败或表现不力时动态重分配角色、允许互相顶替）。软件开发、工具使用、科学推理上均显著优于既有系统。
- **Zero-Shot Coordination（2611.06409）**：ZSC 在 RL 里研究得多，LLM agent 场景下却常依赖**实际不会共享的专用脚手架**。这篇改用**极简通用脚手架 + 隔离特定协调难题的最小环境**，结论是：即便在这种受控条件下，前沿 LLM agent **协调得很差**，主因是**对协调问题本身理解不足、以及对「同伴信念」的推理太弱**；LLM 引入的语义信息本可成为新的协调轴，却没能被有效利用。作者提出 Coordination-friendly definitions，并证明可**自动发现**，免去手工工程。
- **Airlock（2611.06727）**：多智能体作用于外部世界时，**单个 agent 的错误输出会在被发现前跨任务扩散**，形成系统级 blast radius。已有控制要么只取消出错源、漏掉下游消费者，要么整条工作流停摆回滚、牺牲健康工作。Airlock 的树状运行时 **EdgeCitadel** 纵向收窄父子权限以建立节点边界与控制开关，**仅追加的 provenance DAG** 横向记录跨 agent 数据消费；告警后向前在 DAG 上隔离受污染执行与待决动作，向后收敛根因。默认档「冻结受影响分支」，优化档用 **fence-then-prune** 执行**截止期感知的最小割**以最小化附带损失。1,832 次 testbed、161 次真实智能家居 LLM 运行、24,266 条仿真记录：**所有告警后错误动作全部被阻断、收敛后零泄漏**；A2A 与 LangGraph 原生控制最多只围住 33.3% 的故障或最多保住 16% 的工作。
- **SecureGARD（2611.06682）**：把「间接 prompt injection」变成**执行层安全问题**。既有防御约束工具调用、轨迹或信息流，但**动作语义、状态依赖与证据关系始终是隐式的**，跨异构工具难泛化、难安全更新。SecureGARD 把异构调用落到共享语义表示，用**可执行本体 + episode 级任务状态**推导确定性的 **ready / waiting / forbidden** 判定——「waiting」表示未满足但可恢复的义务，从而支持**有界重规划而不扩张授权边界**；本体离线演化，只有能修复训练失败暴露的本体错误、保持逻辑一致与受保护蕴含、且通过留出验证的 LLM 提议公理才被接受。在 AgentDojo、ASB、AgentDyn 的正常与间接注入设定下**三个基准 ASR 全为 0%**，且攻击下的任务效用优于既有基线。
- **Using Experience Twice / ORSD（2611.06543）**：轨迹里既有成功也有失败决策，稀疏的轨迹级奖励分不清「该强化哪个关键决策」。做法是**从同组轨迹间的行为差异中蒸馏出自然语言过程评分表（process rubric）**：策略在每步独立生成多组 rubric，冻结的 verifier 对每条轨迹逐项打分，按「rubric 满足度与任务成功的对齐度」选一组，在训练时把该组当作**特权信息**，比较「有/无 rubric」两种条件下原始 token 的对数似然，**似然差即 token 级过程信用**，再与轨迹级 GRPO 优势相加。
- **Turn-Level Best-of-N（2611.06868）**：推理期扩展的简单做法——生成器每步产出 N 个候选动作，选择器直接比较并挑一个执行。问的是**现成开源权重 LLM 能否直接比较候选动作**（此前工作依赖 critic 模型）。长程终端任务上准确率 **+5~10%**、重复尝试一致性提升，轨迹分析显示行为向更优模式迁移（尝试次数下降、指令遵循与调试测试变好）。

### 记忆、上下文与 harness

- **Route to Remember（2611.05636）**：生产 agent 的记忆**几乎全由文本构成**，每次新查询都要付「随历史增长」的额外代价。**权重记忆**把知识内化进参数、回答时完全不用上下文，在自进化 agent 里已被证明能内化技能与行为，但在**情景/语义记忆（如用户专属事实）**上仍鲜有探索。用**在策略自蒸馏（OPSD）**训练一个「无上下文学生」，教师是同一模型但条件化了用户记忆；再加**先验证后重生成的路由器**，让权重记忆与文本记忆各自覆盖擅长的查询。HaluMem 上**匹配或超过强文本记忆基线（含全上下文提示与检索系统），且每次查询读取的 token 更少**。
- **SUMONE（2611.06445）**：已有可学习压缩方法多依赖下游任务结果或 solver 行为，把训练**耦合到具体任务或 agent**。SUMONE 是独立摘要器，用**掩码重建**训练：给出过期历史的摘要，冻结的重建器恢复原轨迹中被随机掩蔽的部分，**重建质量 + 长度惩罚**构成任务无关奖励，用 GRPO 优化摘要器——**自监督直接来自原始轨迹，不需要参考摘要也不需要跑下游任务**。推理期只保留轻量摘要器，可即插即用地压缩未改动的 agent。DeepSearchQA 推理成本降约 **78%**、SWE-bench Verified 降 **75%**，**同一 checkpoint 可跨下游模型与 harness 迁移**。
- **Tools Need Not Speak in Text / Coca-Cola（2611.06500）**：质疑「agent 必须把工具输出当显式文本 token 消费」这一前提。Coca-Cola 是**连续潜变量**上下文压缩模型，把工具观察压成 latent token 并**直接嵌入 agent 的输入嵌入空间**；配合 **Action-Preserving Training**，对齐全量与压缩观察下的 next-action 分布，使压缩模型学到**保留决策关键信息的 action-sufficient latent token**。网页搜索 agent、四个 QA 基准、两个模型族上，**token 消耗降 70.01~89.24%、端到端运行时降 24.45~55.97%，且任务表现一致提升**。
- **Does Context Compression Preserve Refusal Alignment?（2611.06380）**：**语义保真不等于行为保真**。编码器式压缩在重建保真度很高的同时，**系统性削弱**指令微调模型的拒答行为，且跨模型族与压缩架构稳定复现；机制分析显示压缩**衰减了沿解码器「已学会的拒答方向」的激活**。**Memory Steering** 这一轻量推理期干预（完全在压缩表征空间内、不重训）把拒答率恢复到接近基线。
- **When Do Summaries Become Instructions?（2611.06545）**：长跑 agent 压缩上下文时，写下的交接摘要可能**陈述记录并不支持的权限或要求**。方法很硬：合成工具使用任务带**真值权限账本**，再做**同快照重放**——把被标记的整句替换成中性填充后重跑后继实例。两个 AI 读者确认：两个开源权重模型的**可读摘要中 1.2% / 2.4% 含无依据的「限制」，0.1% / 1.3% 含无依据的「授权」**。把虚假批准中性化后，**120 次留出运行中的越权动作从 24 次降到 7 次**。多数「开发期限制」其实来自 agent 先前推理中「此事需要审批」的判断。**把系统提示里「有些操作需要审批」改成说明要求来源，限制类无依据句从 5.0% 降到 1.8%（留出模板 1.8%→0.3%，p<1e-9），而账本确实要求的审批请求几乎不变**。
- **The Harness Is the Model（2611.06116）**：银行验证的是模型，部署的却是**系统**——决定模型看到什么、能调什么工具、谁复核其动作的 harness。固定模型、换 harness：4 个开源权重模型 × 5 种 harness（单次结构化决策流水线 / ReAct 工具循环 / 政策只能靠检索触达 / 带长篇良性客户记忆 / 带同模型合规审阅者），在模拟零售银行的 156 个预注册案例（11 个规则族改写自欧盟消费信贷、支付、投资者保护、数据保护与反洗钱条款）上跑 **3,120 个双轮 episode，全部按执行工具轨迹确定性打分**。**汇总看 harness 只把正确率在 87.3%~92.1% 之间挪动；但模型内部差异巨大**——某个模型最好与最差 harness 相差 **11.5 个百分点**，足以让它在四个模型里**从第一掉到末位**，另一个模型则完全无差异。同模型审阅者把违规从 **9.6% 降到 6.4%** 且没有推高过度拒答——与预注册预测相反。
- **HarnessFlow（2611.06254）**：harness 设计仍靠手工，而自动化需要在**开放式搜索空间**里做昂贵的端到端评估。HarnessFlow 把候选与评估历史组织成**精炼树**，用 **MCTS** 策略平衡探索与利用，由**编码 agent** 结合归档代码、执行反馈与可复用 harness 机制库来改写选中的 harness；模型与任务环境固定，候选评估预算受限。六个基准（agentic、编码、网页交互）上**平均测试分最高**，优化后 harness 平均 **69.48%**，比初始 harness 与 Meta-Harness 分别高 **10.89 / 3.95 pp**，且**每任务执行成本低于手工基线**。
- **A Compositional Knowledge Architecture for a Shared Organizational Cortex（2611.05753）**：组织积累的是**证据**，行动靠的是**解释**——由若干观察拼装、依赖假设、并随情势修订的判断；现有检索、知识图谱与 agent 记忆**留住记录却丢掉解释**。提出四层架构 **Signals / Domains / Claims / Dimensions**：解释连同其**理由与当前成立度**一起持久化，由**真值维护网络**随证据变化修订成立度，并让经校验、带版本的 Dimensions 把解释定位在命名坐标轴上。注册检索实验中 Dimension 项 **nDCG@10 +0.028（p=0.002）**；系统级对比中完整配置比「仅 Signals」**+0.081**、比「图增强的仅 Signals」**+0.053**（均 p<0.001）。
- **FlyHash for LLM Agent Memory（2611.05791）**：把果蝇嗅觉回路的 **LSH（稀疏随机投影 + winner-take-all）** 首次用到 agent 记忆检索。三个「从业者真会问」的问题：按**匹配位数协议**的**质量优势成立**（10 个种子、四个数据集、两种模态，且顺带发现并纠正了一个此前未记录的对比陷阱）；但**优势换不成实际记忆/延迟收益**——等位下 FlyHash 码比 SimHash **更大也更慢**，而 HNSW 在常规规模上**碾压两种哈希**；作者新引入的稀疏集合比较只挽回朴素延迟差的一部分，**哈希的实际适用面比质量结论窄得多**。
- **Graph-Mediated LLM Systems（2611.05953）**：图在 LLM 系统里承担结构推理、知识接地、检索与记忆，进入 agentic 时代还组织**执行依赖与多智能体通信**，把中间观察与留存信息连到后续决策。这篇综述提出**操作级「角色-位置」分类法**（推理 / 知识与证据 / 检索与记忆 / 执行 / 协调），比较图观测与外部计算如何引导决策、记忆表示与更新如何支撑后续任务、依赖如何约束执行与信息投递，并**区分局部指标提升与下游任务表现**，再把基准、对比设计、过程诊断与系统成本整理成评测框架，指出自适应计算与停止、记忆维护、依赖感知恢复三个开放挑战。

### 安全、对齐与评测

- **Signed, Sealed, Leaked（2611.06585）**：**签名认证 ≠ 行为良善**。作者用一个**合法签名的 MCP 工具**把敏感数据塞进发往「策略允许的目的地」的请求里做演示：**Meta 的 MCPGuard-Dynamic 在同一次运行里挡住了直接外传，却每一次试验都没挡住这个变体**。方案是 **germline execution**——不检查也不信任工具实现，而是**限制信息披露**：每次调用在**从无数据「胚系」进程 fork 出的临时副本**里运行，副本只拿到对该目的地授权的信息，**即使恶意代码执行，它能外泄的内容也被其副本可见的数据上限所界定**。在「副本封闭性 + 胚系无数据」假设下，论文对每个已签名发布证明**汇点无干扰性**，并在确定性重放模型下证明可验证见证可确立流违例。**153 次攻击运行中胚系执行零未授权披露，而基线防御与消融组为 5.9%~74.5%**。
- **A.S.E 2.0 / CASE-Bench（2611.06294）**：编码 agent 在生成代码前先构造**仓库上下文**，对安全敏感代码而言，这个上下文决定模型看到的是**项目的安全护栏**（如授权检查）还是**可供模仿的不安全代码**。论文构造 **CASE-Bench**：来自 51 个项目真实 CVE 的 145 个仓库级任务，Docker 运行、含功能测试与**双向验证的 PoC 利用**，并标注「哪段仓库代码在支撑或破坏安全」。用 13 种上下文构造方法 + 6 个对照组、6 个 LLM：面向功能的上下文把功能通过率最多提高 **8.2 pp**，但安全通过率最多只 **3.7 pp**；**抽掉一个护栏最多降低 8.1 pp 安全通过率，而插入一个不安全范例最多把「正确但可被利用」的代码抬高 6.3 pp**；**编码 agent 只在 27~36% 的轨迹里真正看到了相关护栏**。
- **Does Frontier AI Strengthen Cyber Defense?（2611.06629）**：以 **Project Glasswing** 为自然实验——少数大型美国科技公司提前拿到用于找漏洞的 Claude Mythos Preview。以全部公开披露漏洞为样本：**有访问权的公司披露量相对中俄同行翻倍以上**，**高影响漏洞多披露约 150%**，而修复速度不变。随着受助公司自己找到更多漏洞，靠赏金卖发现的**外部研究者在其代码里报告的漏洞约减半、转而在别家公司报告，却没有离开市场**。**没有证据显示攻击者利用了新增漏洞**：披露后一个月内被利用的占比下降约三分之二，主要因为披露时已被利用的比例变小，而**被利用的数量没变**。作者提醒：受限发布在**不同国家的公司之间制造了软件安全的不对称**。
- **Agent-as-a-Judge 的确认偏误（2611.05662）**：开放式 agent 任务越来越依赖「给评委工具与完整轨迹、让它自己去环境里取证」的 Agent-as-a-Judge，前提是**自己取证就该被证据接地**。论文证明**接地并不能免疫确认偏误**：一条**不承载任何证据、只挂着权威来源**的虚假预筛注记，能**翻转最多 40% 的工具型评委原本正确的裁定**（跨 4 个评委、5 个数据集），**即使评委随后收集到了决定性证据**。行为变化归为三种失效模式——**过度信任**（验证完、结论也对，然后改口）、**幻觉**（编造支持翻转的理由）、**调查不足**（在第一个佐证信号就停）；两个 Claude 评委的翻转以**过度信任为主（67~75%）**，小模型评委则三种分散，轻量缓解**只能削弱、不能消除**。
- **Mass Producing Training Data with Surprising Side Effects（2611.06324）**：训练数据会在训练域外引发意外行为（不安全代码数据诱发广泛失准、过时鸟名诱发 19 世纪人格），但这类样本只有几十个手工构造、难以系统研究。论文**自动搜索「意外副作用数据集」**：三个目标（诱发目标行为、读起来像普通后训练数据、对人类审阅者而言是意外的）都用 LLM 评委操作化，用演化、强化学习与 subliminal learning 搜索，经留出指标重打分与过滤后产出 **6,575 个 DSSE、覆盖 8 种行为**，其中许多**跨模型族与尺寸泛化**。自动化指标与 ML 研究者的判断一致，且**前沿模型预测副作用的能力超过人类**。
- **Addition by Subtraction（2611.06553）**：安全对齐可能**极其稀疏**——剪掉少量安全关键神经元或消融单一拒答方向就能显著破坏对齐行为。论文的做法是**在微调过程中逐步移除已识别的安全关键神经元**，再用偏好优化**让模型经由其他部分重建安全行为**。结果对剪枝攻击显著更鲁棒，且**收益外推到白盒之外的场景**——对拒答方向消融等其他稀疏性干预、以及广泛的**黑盒越狱攻击**同样有效，攻击成功率在某些攻击下**最多降低 90%**；微调模型**真实性提升**且大体保留通用能力，覆盖三家厂商四个模型。
- **Who Gets Counted?（2611.06550）**：从姓名推断性别/种族/族裔的**标准工具恰恰误分类了多样性研究最需要测量的群体**，而 LLM 被提议作为解法。跨 **10,000 个中文姓名、19,998 名自报种族的北卡选民、300 名有人工参考编码的政治学作者**，论文比较 3 个 LLM 与 7 个传统工具：**选择性标注**解释了 LLM 准确率优势的一部分——**Claude Haiku 只标了一半选民，而一个只用最高置信一半的传统工具反而更准**。所有工具的硬标签都**把白人与黑人在民主党注册上的差距低估了 36%~65%**，而基于 BISG 后验的 **BIRDiE 估计误差在 0.03 以内**；Haiku 缺失的标签**按年龄选择**，把年龄差距**虚增六岁**。结论：**分类器应以它产出的估计来评判，包括缺失标签的后果**。
- **AgentTrustCI（2611.06674）**：基础设施安全**不能保证** agent 选了允许的工具、把答案接地在工具输出上、或遵循了必需的工作流。AgentTrustCI 是 Java / JUnit 5 框架，把这些应用层期望表达为**策略、接地与轨迹检查**并作用于录制轨迹，配套确定性重放实现支持**可重复的构建期测试**，另有 judge 接口作为可选语义评测扩展点。55 个覆盖七个企业领域的合成案例上，**完整流水线正确分类全部 30 个注入故障与 25 个通过对照（含 10 个非平凡对照），且 12 个指定关键案例无一漏判**；单层配置只能正确分类 35 例（语料刻意按层隔离故障）。作者明确声明：结果证明的是**所编回归套件的覆盖度，不是生产准确率**。
- **Trace2Eval（2611.06506）**：编码 agent 的下一代评测应**从真实交互轨迹里持续再生**基准，而不是固定任务 + 参考补丁。Trace2Eval 用**多 agent 重建系统**分析过滤后的轨迹、还原原始用户请求、把工作区恢复到交互前状态并**重建轨迹等价的执行环境**；候选 agent 执行重建后的请求产出初始产物，再用**跨标注者对齐迭代精炼的人工 rubric** 与**用源码和运行时证据校准的评委 agent** 评分。按流水线反馈修改产物后，**19 个模型-harness 配置平均提分 10.05 pp**，DeepSeek-V4-Pro 配 Claude Code 最高 **19.28 pp**——说明 rubric 反馈是**可操作的改进指引**而非打分噪声。
- **Task-Efficient Agent Evaluation Using Cached Traces（2611.06803）**：高效评测只跑少量任务就外推全量表现，传统做法只用**二元正确性**；而 agentic 系统每次执行都产出**信息量丰富的 trace**。论文用 LLM 抽取结构化摘要并用标准文本编码器嵌入，得到**保留正确性/任务信号、但剥离系统身份/模型族/harness 信号**的 trace 表示（后者主导原始 trace 嵌入）。据此构建参考系统的低维表示并由几何位置预测新系统分数：**SWE-bench Verified 上平均绝对误差 0.13 → 0.08、Terminal-Bench 2.0 上 0.14 → 0.12**（仅提供**一个**随机执行任务时）。
- **GH-AWTrace（2611.06866）**：面向仓库的 agentic workflow 现有研究只看**定义与产出**，对**执行中发生了什么**证据有限。GH-AWTrace 把 **25,014 个已验证的 GitHub Agentic Workflow（5,051 个仓库）**关联到 **4,112,526 条运行记录与 562,877 份非空执行日志归档**，在 GitHub 日志保留期限约束下保留执行证据，并关联仓库元数据与生成的 workflow 配置。示例案例显示日志能暴露**工具拒绝、provider 失败、agent 改变做法、以及 agent 之间的委派**，可用于研究执行失败、工具使用，以及**上报运行结果与可见任务进展之间的落差**；覆盖率参差且日志是**局部观察而非完整轨迹**。
- **FrontierPhysics（2611.06910）**：现有物理基准只考固定问题、孤立子任务或给定解答的复现，**很少同时检查研究质量与正确性**。FrontierPhysics 是端到端基准：**42 位物理学家基于自己的研究出 56 道题**，覆盖九个理论/计算/实验领域，每题要求 agent **读文献、制定研究计划、做研究实验、产出结构化结果与科学手稿**，并以确定性验证器 + 专家 rubric 评判「研究是否正确且可发表」。**22 个模型 26 种配置中，没有一种配置的通过数超过 168 次 rollout 中的 46 次**；人工审阅轨迹显示前沿 agent 的主要短板是**推理不够严谨、专家直觉不足**，而非物理知识缺口或执行错误。
- **ServerBench（2611.06841）**：让编码 agent 为**自己所用**的推理服务系统做设计。目标函数是**每美元 GPU 成本产出的「延迟合格 token 价值」**，状态化重放保留会话依赖，独立验证检查提交的系统。11 个编码 agent 模型 × 3 种部署：**Claude Sonnet 5.5 在 Gemma E4B 上做到 2.97 美元/美元（vLLM 参考的 4.87 倍）**，33 次运行中 22 次产出**通过验证**的系统、13 次超过最强基线。三条发现：高价值设计会把**容量改进与负载选择协同**；agent 通过**与负载相关的实验**解读性能反馈；可靠交付要求**验证优化引入的执行路径**。
- **CompressionBench（2611.06858）**：递归自我改进要求 AI 改进后续系统所用的模型与基础设施，**LLM 压缩**是具体效率目标：在更小存储预算内保持预训练模型行为。论文把压缩作为**终止任务**：agent 拿到源 checkpoint、存储上限、推理环境与时间预算，自主构造压缩权重与可执行推理代码，以困惑度反馈引导搜索，独立验证最终模型。六个 agent × 六种模型-尺寸设定，**36 份提交中 29 份通过验证**；按任务选最优 agent 设计，平均较 BF16 **困惑度仅升 3.4%**、下游准确率 **77.33%**（BF16 为 79.56%）。实验记录揭示机制与失效：agent 在 **24 次修订中的 21 次**近乎固定存储下降低困惑度；**全模型反馈推翻了 79 次局部排序中的 17 次**；**生成与推理测试暴露了单看似然会漏掉的失败**。
- **Mechanical Engineering Skills（2611.05758）**：机械工程的 CAD、仿真、制造工具各有独立接口与学习曲线，本工作给出**33 个开源 agent skill** 的库，让这些能力通过一次文本或语音对话即可使用。每个 skill 结合**操作说明、可执行工具与验证流程**；语言模型负责理解请求与选择/协调 skill，**确定性工具负责计算并返回已校验结果**。默认工作流不需要工具特定训练、本地模型执行或微调，skill 按需加载、一条命令安装；其中 **19 个 skill 改编自作者实验室已发表或预印本研究**（文本转 CAD、连杆综合、CFD 配置、应力场与晶格代理、方程发现、增材制造规划与过程监测），另 14 个覆盖核心工程与教学。五个带证据范围与独立复跑的案例给出**晶格均质化的解析级一致、火箭远地点与 OpenRocket 存档值相差 4% 以内、未见温度下比三次多项式精确 9 倍的方程拟合**，以及孔隙率监测的端到端演练。
- **Today's Work, Tomorrow's Workforce（2611.06346）**：AI 辅助让工作者在「自己解」与「接受 AI 的答案」之间选择，**可能挤掉习得与保有技能所需的练习**——包括监督 AI 所需的那部分技能。论文把 accept-or-solve 模型扩展到**技能随独立练习与依赖 AI 演化的任务序列**，对比**短视工作者**（最大化即时效用）与**策略性工作者**（同样看重未来技能）。结论：**新手会陷入低技能陷阱，专家可能丢失技能——即便 AI 辅助的结果准确率仍然很高**；策略性工作者则可能**在 AI 更准时仍选择自己解**，因为他们看见技能的未来价值。激励侧：奖励「正确的独立工作」可以把技能获取与保有变成**自我维持**（一旦技能足够，独立工作可自持，不再需要持续激励），且**提高技能目标反而可能降低长期激励成本**。

## 4️⃣ 对本机 OpenClaw 运行时的可操作含义

1. **本机正在踩的正是 2611.06116 的结论。** 该文证明：模型固定时，harness 能把正确率在模型之间挪动 11.5 个百分点，足以改变排名。本机的 harness（cron 触发方式、fallback 链、lane 隔离、announce 投递）就是我们的「harness」——**当前 openclaw-news-digest 的失败恰恰不在模型层，而在收尾环节**（SESSION_PLACEMENT_TURN_SETTLEMENT_CLOSED）：内容生成与飞书推送都成功，agent turn 却在结算阶段失败并把作业标成 error(7x)。**先把「harness」当成一等公民排查对象，比换模型更划算。**
2. **把 SQLite 会话回收当成待治理的共享资源。** SQLite session reclamation commit checkpoint expired 的机制是：主线程与回收 Worker 用 SharedArrayBuffer 做提交授权握手，**5 秒**内拿不到授权就抛错（COMMIT_DECISION_TIMEOUT_MS = 5e3）。它只在**多 lane 并发写同一会话库**时出现，所以受难的全是 target=main 的作业（heartbeat:main 22x、main 宿主的 NightOps）。可立即尝试的缓解：**错峰 heartbeat 的 30 分钟节奏**（当前 7 个 agent 的 heartbeat 几乎同相位触发）、**减少同时进行的 NightOps 路数**；根治需上游修复或升级。
3. **交接摘要就是我们的夜班报告，而 2611.06545 说它们会自己长出「政策」。** 该文用真值权限账本证明：agent 自写的交接摘要有 1.2%~2.4% 含**记录不支持的限制**、0.1%~1.3% 含**无依据的授权**，且中性化虚假批准能把越权动作从 24/120 降到 7/120。**我们的 nightly-scout-*.md 与 memory/*.md 正是后继实例的交接摘要**——建议在这些文件里把「事实 / 推断 / 建议动作」**分栏标注**，并像论文那样在交接处写明**权限与前提的来源**（这正是论文里把系统提示改成「要求来自哪里」后，无依据限制从 5.0% 降到 1.8% 的低成本修法）。
4. **2611.06585 直接命中本机的 MCP 信任边界。** 本机装有第三方 MCP server（Tavily 搜索、memory-lancedb-pro 等）并以客户端身份访问他人 server。论文的结论是**签名认证不能替代行为治理**：一个合法签名的工具可在策略允许的目的地上夹带外泄，Meta 的 MCPGuard-Dynamic 在其演示中**每次都没拦住**；而 germline execution（每次调用在无数据胚系进程 fork 出的临时副本里跑）把 153 次攻击的未授权披露从 5.9%~74.5% 降到 **0**。**可操作项**：本机若有自建 MCP server，应把「调用副本只持有该目的地授权的数据」纳入设计；同时**不要接受任意 redirect_uri**（与 11-05 窗口的 119 个 OAuth MCP server 中 95.8% 接受任意 redirect_uri 互为印证）。
5. **上下文压缩会悄悄削弱拒答能力（2611.06380），而本机正重度依赖压缩。** 论文证明编码器式压缩在重建保真度很高时仍**系统性削弱拒答**，机制是**衰减沿「已学会拒答方向」的激活**，且 Memory Steering 可在压缩空间内推理期恢复。对本机的含义：**MEMORY.md / lancedb 自动召回 / 长会话压缩**这些路径上的拒答行为需要单独回归测试，不能用「语义保真度」当作安全指标；同时 2611.05306（频繁压缩几乎不损失任务准确率）与 2611.06500（潜变量压缩降 70~89% token 且表现更好）说明**压缩仍是本机最划算的优化方向**。
6. **Airlock 与 SecureGARD 给出多 agent「出错爆炸半径」的两种治法。** 本机多 agent 共用一台 WSL2 主机、共享同一 SQLite 与内存：单 agent 的故障输出会在被发现前跨任务扩散（这正是 70 次 SQLite 回收超时导致成片作业失败的形态学）。**Airlock 的最小割思路**（告警后只冻结受污染分支、保留健康工作）与 **SecureGARD 的「ready / waiting / forbidden」语义治理**都提示：**cron 失败应按依赖图局部隔离，而不是整条链路停摆**——例如 heartbeat:main 连续失败 22 次时，其它 agent 的 heartbeat（scout/life/coder/finance/health/work/orchestrator）本应被显式判定为「可跳过」而不是「整组重试」。
7. **本地基准缺口值得自己测一次 GDPx 式任务。** SemiAnalysis 的 GDPx 说明**知识问答式基准会严重高估 agent**：最强者在真实工作环境只有 12%，且金融/法律因「一个数错全废」而**无一完全解决**。本机的 cron agent 每天做的正是「真实工作」（抓取、生成、推送、故障处理）——建议把**本机日报生成链**当作一个 GDPx 式任务集，长期跟踪「端到端完成率」而不是「单步成功率」；本轮已知端到端完成率 = 8/10（含 1 次 fetch 脚本因引号错误全灭、1 次 alignment 域名不可达）。
8. **可观测性数据源已经现成。** GH-AWTrace（25,014 个 workflow / 412 万条运行记录 / 56 万份日志）与 Trace2Eval 都指向同一件事：**从真实执行轨迹重建评测基准**。本机的 /tmp/openclaw/openclaw-YYYY-MM-DD.log 每天已产出 4~7 MB 的结构化 cron/模型调用日志，**可以直接当 trace 语料用**，配合 Trace2Eval 的「结构化摘要 + 嵌入」表示（把 MAE 0.13→0.08）做**少样本外推全量表现**，用于判断「该不该重启 gateway」「该换哪条 fallback」这类决策，而不必每次全量跑。
9. **技能库应当写成流程而非知识（延续 11-05 结论）并配静态闸门。** 2611.05758 的 33 个机械工程 skill 遵循同一模式（操作说明 + 可执行工具 + 验证流程，确定性工具负责计算、模型只负责选择与协调）；11-05 的 2611.05088 则给出**不执行、不调工具、不生成 token** 即可在 prefill 阶段筛出恶意 skill 的检测器（池化 F1 99%、中位 259~284 ms）。本机每次安装 skill 前应跑这道静态闸门。
