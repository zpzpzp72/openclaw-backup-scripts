## 🔴 exit 1 的真因(纠正我 10-28 的误判)

**我上一轮说「NAS 写满 → gzip I/O error → tar exit 1」是错的。** 事实:
- `gzip: stdout: Input/output error` 只出现在 **2026-10-03/04/05** 三次(日志行 1942/1956/1970),是 10 月初的历史记录
- **10-28 与 10-29 当次 tar/gzip stderr 行数均为 0**
- exit 1 真因 = **备份期间源文件被改/被删**:
  - `.openclaw/.sync-staging/**` 被 claw-sync 清理 → `File removed before we read it`
  - `agents/main/agent/openclaw-agent.sqlite` 正在写入而缩小 → `File shrank by 532480 bytes`

**教训**:`exit 1` 与「归档损坏」是两回事;判断完整性要看 gzip 层是否有 I/O error + 归档大小是否合理,不能凭退出码推断。
