## ✅ 10:45 修复 Gateway service config 三条问题（ZP 报障）

**报障内容**（`openclaw gateway status` 贴图）：
1. `Gateway service PATH missing required dirs: /home/zhiping/.local/share/pnpm/bin`
2. `Gateway service PATH includes version managers or package managers`（`~/.nvm/versions/node/v26.10.0/bin`）
3. `Gateway service uses Node from a version manager; it can break after upgrades`（`~/.nvm/versions/node/v26.10.0/bin/node`）

**根因（源码级定位，非猜测）**：
- 判定逻辑在 `dist/service-audit-D-KyNX3q.mjs` 的 `auditGatewayServicePath()`：
  - `expected` = `getMinimalServicePathPartsFromEnv()` 算出的最小 PATH
  - `missing` = expected ∖ service PATH
  - `nonMinimal` = service PATH ∖ expected 且 `isNonMinimalServicePathEntry()`（含 `/.nvm/`、`/pnpm/` 段）
- 判定 3 在 `auditGatewayRuntime()`：`isVersionManagedNodePath(execPath)` 命中 `/.nvm/` 即报
- unit 里的 `ExecStart` 与 `Environment=PATH` 都被旧 installer 写成了 nvm 版本目录

**修复动作（最小改动，2 行）**：
1. 装系统级 node（不进版本管理器）：`/usr/local/lib/nodejs/node-v26.10.0/bin/node` + 软链 `/usr/local/bin/node`（真实副本，非 nvm 软链，避免 `isVersionManagedRealNodePath` 命中）
2. 改 `~/.config/systemd/user/openclaw-gateway.service`：
   - `ExecStart=/usr/local/bin/node --max-old-space-size=4096 <原 dist/index.js 路径> gateway --port 18789`
   - `Environment=PATH=/usr/local/bin:/usr/bin:/bin:/home/zhiping/.local/bin:/home/zhiping/.npm-global/bin:/home/zhiping/.bun/bin:/home/zhiping/.nvm/current/bin:/home/zhiping/.local/share/pnpm/bin:/home/zhiping/.local/share/pnpm`
3. 建 `~/.nvm/current` → `versions/node/v26.10.0` 软链（让 `.nvm/current/bin` 成为稳定路径，不含版本号段）
4. `systemctl --user daemon-reload`（**未重启**，运行中进程不受影响，18789 一直在线）

**验证**：`openclaw gateway status` 重跑 → 三条 `Service config issue` 全部消失，`Connectivity check: ok`，`Runtime: running (pid 319857)`。

**关键教训**：
- 诊断这类「配置看起来不对」的问题，直接 `openclaw gateway status` 看它报什么不够——**必须去 dist 里找判定函数**，才知道它到底比对了哪两个集合。否则只能猜。
- 修 systemd unit 属于「配置变更」，按 AGENTS.md Red Lines：先备份（`openclaw-gateway.service.bak-<ts>`）→ 保留原有 `Environment=OPENCLAW_SERVICE_MANAGED_ENV_KEYS`、`EnvironmentFile`、drop-in（`litellm.conf`）、`--max-old-space-size=4096`、端口 18789 → 只改 PATH 与 node 路径两行。
- `openclaw message send` 是长连接阻塞式，前台跑会被工具超时打断；**应改用 `sessions_search` 查群会话确认投递**，而不是盯着 CLI 返回。
