## 🔴 修正:我 11-04 说「2026.10.9 无 node 版本障碍」是**错的**

权威依据(npm registry):
| 版本 | engines.node | node v26.10.0 是否满足 |
|------|-------------|------------------------|
| 2026.10.9 | `>=24.22.1 <25 || >=26.12.1` | ❌ **不满足**(需 ≥26.12.1) |
| **2026.10.10** | `>=24.16.0 <25 || >=26.1.0` | ✅ **满足** |

**我当时的判定错在哪**:
- 我用 `npm install openclaw@2026.10.9` 「成功」作为证据 → **假象**
- npm 的 engines 检查在**默认配置下只警告、不阻断安装**(除非 `engine-strict=true`)
  → 我那次用了 `--ignore-scripts`,更是完全绕过了检查
- 因此「装上了」不等于「engines 满足」

**修正后的正确结论**:
- 升级 **2026.10.9** 需要先把 node 切到 **v26.12.1**(nvm 里已装)
- 升级 **2026.10.10** **无 node 障碍**(当前 v26.10.0 直接满足)
- npm latest 已是 **2026.10.10**(beta = 2026.11.5-beta.1,extended-stable = 2026.9.36)

**教训(已记 ERR-20261104-004)**:
> **「安装成功」不能作为「engines 满足」的证据。** npm 默认只警告不阻断。
> 权威判定必须是:读 registry 的 `engines` 字段 + 用 semver 库判定,
> 或 `npm_config_engine_strict=true npm install` 让它真正拦截。
> 这与 v33「连工具输出的数字也要二次采样验证」同源:**二手证据(装上了)不可信,一手规则(engines 字段)才可信。**
