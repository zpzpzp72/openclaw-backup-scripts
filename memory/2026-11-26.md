# 2026-11-26 日记

## ★ 事件：GitHub push protection 拦下 Mapbox token（public 仓库）

### 经过
```
05:32  push 被拒:
  remote: —— Mapbox Secret Access Token ——
          - commit: 458b1043...
            path: scout-raw/lw-1126-sandbox.html:4
  error: failed to push some refs
```

### 取证结论
| 项 | 结论 |
|----|------|
| 远端历史（1907 个 blob 严格扫描） | **0 硬密钥、0 pk. token → 未泄漏** |
| 该 token 性质 | Mapbox **公共** token（`pk.` 前缀，设计上可公开嵌前端），来自被抓网页的 JSON：`"mapbox":{"apiKey":"pk.eyJ..."}` |
| 根因 | Scout 抓网页**原样入库**，页面内嵌的 apiKey 未脱敏 |

### 三处修复
1. **内容脱敏**：`scripts/sanitize-secrets.py`（硬密钥 / pk. token / apiKey 字段三类）
2. **流程接入**：给 fetch 脚本的 `grab()` 注入脱敏调用（已注入 4 个）
3. **push 前闸门**：`scripts/pre-push-secret-guard.{sh,py}` + `.git/hooks/pre-push`

### ★ 过程中踩的两个坑（都值得记）

**坑 1：闸门用了 `grep -E` 的 `(?<!)` 后顾断言 → 静默失效**
```
grep: warning: ? at start of expression
（且退出码仍为 0 → 闸门「通过」）
```
ERE **不支持**后顾断言；`grep -P`（PCRE）才支持。
→ **一个「校验器自己静默失效」的闸门，比没有闸门更危险**：它给出虚假的安全感。
→ 已改为 python 实现（可靠）。

**坑 2：脱敏了工作区，但 commit 里还是旧内容**
```
工作区文件命中: 0    ← 脱敏成功
HEAD 内命中:     1    ← commit 里是脱敏前的版本
```
→ push 的是 **commit 内容**，不是工作区。必须 `git commit --amend`。
→ **凡是要改写「已进入 commit 的内容」，改工作区后必须 amend，否则改动不生效。**
