## ✅ 00:20 备份摘要推送幂等化(本次 cron 的实质改进)

**问题**:`openclaw message send` 是长连接阻塞式,reminder 触发的推送在工具窗口不足时被砍且**不报错**(10-26 05:02 那次只留 27 字节 stdout,无 JSON 无 EXIT);而 reminder 会**反复触发**,重推同一天摘要 = 刷屏。

**改法**:新增 `workspace/cron-scripts/push-backup-summary.sh`
- 状态文件 `~/.openclaw/.backup-summary-last` 记录**已推送的备份文件名**
- 文件名相同 → 直接跳过(不推送)
- 不同 → 组装摘要 → `timeout 240` 推送 → **仅在返回码 0 且输出含 `"ok": true`** 时才写状态文件
- 失败**不写状态**,下次 reminder 自动重试

**自测**:写入 `openclaw-20261026-0300.tgz` 后跑脚本 → 输出「跳过: 已推送过(幂等)」✅

**配套经验**:`openclaw message send` 的成功判据**必须**是 `sessions_history` 看到消息落地,不能凭 CLI 返回 —— 10-26 05:02 与 10:06 两次的对比已经证明这一点。

## ✅ 15:05 备份脚本三个根因定位并修复(commit b52dd9fe)

上一轮(15:45 那次尝试)因 heredoc 转义失败报 `AssertionError: send_mail 完成邮件块未找到` —— **那次未写入任何改动**(diff 为空),改用逐行定位重写后成功。

### 根因 1:exclude 路径失效 → 每份仍装全向量库
脚本写的是 `--exclude='.openclaw/data/lancedb'`,但**该目录根本不存在**;真实路径是 `.openclaw/memory/lancedb-pro`(下含 `memories.lance/` + `nightly-scout.lance/`)。
→ 模式永不命中 → 每份把 9.4G 向量库整份打包。
**修**:`.openclaw/memory/lancedb-pro` + `.openclaw/memory/lancedb-pro/.memory-write.lock*`。
**排除安全性依据**:插件有 `rebuildFtsIndex()`(store.ts:1595)+ `memory_compact` 工具 → 向量库可从 session/sqlite 重建,属派生数据。

### 根因 2:一封失败的邮件吃掉整条后处理链(真正的病根)
```
send_mail(completion email) 非零退出
  ↓ 脚本 set -e → 整个脚本在此中止
  ↓
cleanup_old 从未执行 → 旧备份自 2026-07-31 起再未清理,堆积 40 份、NAS 98%
最终心跳也从未更新 → last_backup 永远指向上一档
```
**证据链**:日志中「备份完成邮件已发送」**最后一条是 2026-07-30**;07-31 起每天只剩「备份开始邮件已发送」然后断链。**三个症状同一个根因** —— 这也是我最初误当成三个独立 bug 分别排查的原因。
**修**:① `send_mail ... || log "⚠️ ...已忽略,不影响清理与心跳"` ② `cleanup_old` 移到 `send_mail` **之前**(双重保险:邮件失败也照样清理)。

### 根因 3:心跳 last_backup 永远滞后一档
`write_heartbeat` 用 `$LATEST_BACKUP`,而 `LATEST_BACKUP` 在**第 32 行(备份执行前)**解析 → 写心跳时仍指上一档。
**修**:备份成功后立即 `LATEST_BACKUP="$ARCHIVE"` + 重算 `LAST_BACKUP_EPOCH` + `HOURS_SINCE_LAST=0`。

**验证**:`bash -n` 通过;exclude 命中真实路径;`cleanup_old` 调用唯一;邮件日志唯一;旧 exclude 残留 0。原文件备份 `scripts/openclaw-backup.sh.bak-20261027-150445`。
