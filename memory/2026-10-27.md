## ✅ 00:20 备份摘要推送幂等化(本次 cron 的实质改进)

**问题**:`openclaw message send` 是长连接阻塞式,reminder 触发的推送在工具窗口不足时被砍且**不报错**(10-26 05:02 那次只留 27 字节 stdout,无 JSON 无 EXIT);而 reminder 会**反复触发**,重推同一天摘要 = 刷屏。

**改法**:新增 `workspace/cron-scripts/push-backup-summary.sh`
- 状态文件 `~/.openclaw/.backup-summary-last` 记录**已推送的备份文件名**
- 文件名相同 → 直接跳过(不推送)
- 不同 → 组装摘要 → `timeout 240` 推送 → **仅在返回码 0 且输出含 `"ok": true`** 时才写状态文件
- 失败**不写状态**,下次 reminder 自动重试

**自测**:写入 `openclaw-20261026-0300.tgz` 后跑脚本 → 输出「跳过: 已推送过(幂等)」✅

**配套经验**:`openclaw message send` 的成功判据**必须**是 `sessions_history` 看到消息落地,不能凭 CLI 返回 —— 10-26 05:02 与 10:06 两次的对比已经证明这一点。
