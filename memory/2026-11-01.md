**安装要点**
- Ghidra 12.1.4 + JDK 21 (/usr/lib/jvm/java-21-openjdk-amd64): REA 要求 application.java.min=21 且原生反编译器目录匹配 host (linux_x86_64)。bridge 官方验证组合即 12.1.4+JDK21
- Kuna 1.986 是 Apache-2.0 单文件可执行 (Noelo-Lab/kuna), REA 不代装需自备; 该版本真机验证只在 macOS arm64 做过, Linux 属未验证
- Hopper: REA 的 setup --install-hopper 会下载官方 deb + 验 PGP, 但装包走 pkexec → 非交互 exec 无 /dev/tty 会 exit 127。解法: 手动 sudo apt-get install -y <cache>/archive (apt 拒绝无扩展名文件, 需复制成 .deb)。依赖 xvfb/xauth/python3/libx11-6/libxtst6 同样手动装
- IDA: REA 明文不安装/激活/授权。需自带 IDA Pro 9.0+ 与上游 mrexodia/ida-pro-mcp。**上游 main 已是 2.0.0, REA 不认(工具改名), 必须 checkout tag 1.4.0** (attached 档)
- 环境变量写入四处: ~/.profile (登录 shell, 非交互也生效)、~/.bashrc (交互 shell)、~/.openclaw/gateway.systemd.env (所有 agent, 需重启 Gateway)、openclaw.json mcp.servers.rea.env (MCP)
- **未设 REA_ANALYSIS_PROVIDER**: 多引擎并存时 auto 会报 ambiguous, 必须按目标显式 --provider ghidra|hopper|kuna|ida

**端到端实测**: rea decompile-all /usr/bin/true --provider ghidra --output <新目录> → 133 选中/94 written/0 failed, provider=ghidra 12.1.4, 产出 96 文件含真实 .c 伪代码 (如 _DT_INIT)

**踩坑**
- REA CLI 命令名易错: 无 list-procedures, 应是 search / decompile / decompile-all
- decompile-all 的 flag 是 --output 不是 --output-dir; 且输出目录必须**不存在**或加 --resume
- Ubuntu ~/.bashrc 开头有非交互直接 return 守卫 → 自动化场景的 exports 必须同时写 ~/.profile
- pkexec 在无 tty 的 exec 里必失败 (exit 127) → 包管理器类步骤一律自己用 sudo 接管
